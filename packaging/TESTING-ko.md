# Windows 실기 확인 체크리스트 (배포자용)

에리 씨에게 넘기기 **전에** 윈도우 PC 에서 한 번 돌려보고 채우는 문서다.

이 패키징은 전부 macOS 에서 만들어졌고 빌드만 GitHub Actions 의 `windows-latest`
러너에서 돌았다. **윈도우에서 실제로 실행된 적은 없다.** 아래 "미검증" 표시가 붙은
항목은 "아마 될 것"이지 "된다"가 아니다. 여기서 처음 확인되는 것들이다.

에리 씨용 안내문(`はじめにお読みください.txt`)은 이 문서와 별개다. 그쪽에는
저장소나 개발 얘기가 한 줄도 없어야 하므로 섞지 말 것.

---

## 준비

1. GitHub Actions 의 `Windows パッケージ (jpackage)` 워크플로 아티팩트에서
   `Orbit-<버전>-windows-portable.zip` 을 받는다.
2. 윈도우 PC 로 옮긴다. **압축을 반드시 "모두 풀기"로 푼다.**
   zip 을 열어 안에서 바로 실행하면 임시 폴더에서 도는 것이라 결과가 다르다.
3. 가능하면 **JDK 가 깔려 있지 않은 PC** 에서 확인한다. 개발 PC 에서는 시스템에
   깔린 자바가 문제를 가려 줄 수 있어서, 정작 받는 사람 쪽에서만 터지는 실패를
   놓친다. 이 앱은 자체 런타임을 안고 있으므로 JDK 가 없어야 정상이다.
4. Gemini 키는 **아티팩트에 들어 있지 않다.** AI 기능을 확인하려면 본인 키를
   앱 화면(その他 → AI連携)에서 직접 넣어야 한다. 확인이 끝나면 「連携を解除」로
   지우고 넘길 것 — 안 지우면 본인 키로 에리 씨의 요청이 과금된다.

---

## A. 첫 실행

- [ ] **A-1** `Orbit.exe`(표시상 `Orbit`) 더블클릭으로 실행된다 — *미검증*
- [ ] **A-2** SmartScreen 경고가 뜬다. 「詳細情報」→「実行」 로 통과된다 — *미검증*
      - 경고 문구가 안내문에 적은 것과 같은지 확인. 다르면 안내문을 실제 문구로 고칠 것
- [ ] **A-3** **검은 콘솔 창(cmd)이 뜨지 않는다** — *미검증*
      - `--win-console` 을 주지 않았으므로 GUI 서브시스템 exe 여야 한다.
        기동 순간과 브라우저 열릴 때 두 번 다 확인할 것
        (브라우저는 `rundll32` 로 여는데, 이게 창을 번쩍이면 그 자리에서 보인다)
- [ ] **A-4** 30초 안에 기본 브라우저가 자동으로 열리고 Orbit 화면이 뜬다 — *미검증*
- [ ] **A-5** 주소가 `http://127.0.0.1:8080` 이다 (다른 앱이 8080 을 안 쓰는 경우)
- [ ] **A-6** 알림 영역(시계 옆)에 Orbit 아이콘이 생긴다 — *미검증*
      - 숨김(`∧`) 안에 들어가 있을 수 있다
- [ ] **A-7** 기동 직후 "終了するときは…" 풍선 알림이 한 번 뜬다 — *미검증*
      - 윈도우 알림 설정에 따라 안 뜰 수 있다. 안 떠도 치명적이지 않지만,
        안 뜨면 안내문의 "5. 終了のしかた" 가 유일한 종료 안내가 된다
- [ ] **A-8** exe 아이콘이 기본 자바 아이콘이 아니라 남색/금색 원이다 — *미검증*
      - `packaging/windows/orbit.ico` 가 실제로 박혔는지. 작업 표시줄·바탕화면
        바로가기·알림 영역 세 군데 다 확인

## B. 포트 충돌

- [ ] **B-1** 8080 을 쓰는 다른 프로그램을 띄워 둔 채 Orbit 을 실행한다 — *미검증*
      - 확인용으로 아무 서버나 8080 에 띄우면 된다
- [ ] **B-2** Orbit 이 **죽지 않고** 8081 등 다른 포트로 뜬다 — *미검증*
- [ ] **B-3** 브라우저가 **그 바뀐 포트**로 열린다 (8080 으로 열려서 남의 화면이
      뜨면 안 된다) — *미검증*
- [ ] **B-4** 트레이 아이콘에 마우스를 올리면 실제 주소가 툴팁으로 보인다 — *미검증*

## C. 종료 — 여기가 제일 중요하다

- [ ] **C-1** 브라우저 탭만 닫는다 → 앱은 계속 살아 있다(트레이 아이콘 그대로)
- [ ] **C-2** 트레이 아이콘 좌클릭 → 브라우저가 다시 열린다 — *미검증*
- [ ] **C-3** 트레이 아이콘 우클릭 → 「終了 (Orbit を閉じる)」 가 보인다.
      메뉴 글자가 깨지지 않는다(일본어 렌더링) — *미검증*
- [ ] **C-4** 「終了」 를 누르면 트레이 아이콘이 사라진다 — *미검증*
- [ ] **C-5** **작업 관리자(Ctrl+Shift+Esc) → 세부 정보 탭에서 `Orbit.exe` 가
      남아 있지 않다** — *미검증*
      - 이 항목이 이 작업 전체에서 가장 중요하다. 남아 있으면 사용자는 앱을
        껐다고 믿는데 프로세스가 계속 도는 상태가 된다
- [ ] **C-6** 종료 직후 다시 실행하면 정상적으로 뜬다
      (`%LOCALAPPDATA%\Orbit\orbit.lock` 이 잠긴 채 남아 앞을 막지 않는다) — *미검증*

## D. 중복 실행

- [ ] **D-1** 떠 있는 상태에서 아이콘을 한 번 더 더블클릭한다 — *미검증*
- [ ] **D-2** 두 번째 프로세스는 조용히 물러나고, 대신 **이미 떠 있는 쪽 화면이
      브라우저로 열린다** — *미검증*
- [ ] **D-3** "H2 데이터베이스를 열 수 없다" 류의 오류 창이 뜨지 않는다 — *미검증*

## E. 데이터

- [ ] **E-1** 실행 후 `%LOCALAPPDATA%\Orbit\` 이 생긴다 — *미검증*
      - 탐색기 주소창에 그대로 붙여넣으면 열린다
- [ ] **E-2** 그 아래 `db\orbit.mv.db`, `media\`, `logs\orbit.log`, `jwt.key` 가 있다 — *미검증*
- [ ] **E-3** 옷을 등록하면 `media\` 에 파일이 쌓인다 — *미검증*
- [ ] **E-4** **앱을 껐다 켜도 등록한 옷이 그대로 남아 있다** — *미검증*
      - H2 가 파일 모드로 붙었는지를 보는 항목이다. 여기서 옷장이 비어 있으면
        인메모리로 돌고 있다는 뜻이고, 그건 그 자체로 배포 불가 사유다
- [ ] **E-5** Orbit 폴더를 통째로 다른 데로 옮겨도 데이터가 유지된다 — *미검증*
- [ ] **E-6** 앱 폴더 안에는 DB·사진이 **생기지 않는다**(앱 폴더는 읽기만) — *미검증*

## F. 기능 한 바퀴

- [ ] **F-1** その他 → AI連携 에 키를 넣으면 「連携済み」 가 된다
- [ ] **F-2** その他 → 全身写真 업로드가 된다
- [ ] **F-3** 服を追加 에서 사진을 고르면 이름·카테고리·색·種類·素材·シルエット·季節
      이 자동으로 채워진다
- [ ] **F-4** 상의·하의를 몇 개 넣고 홈에서 「AIに選んでもらう」 → 코디가 나온다
- [ ] **F-5** 코디 화면에서 「試着する」 → 전신 사진에 입힌 이미지가 만들어진다
- [ ] **F-6** 記録 탭에 `LOOK 001` 과 날짜가 남는다
- [ ] **F-7** 키를 안 넣은 상태에서도 옷 등록·조회는 되고 AI 만 안내가 뜬다
- [ ] **F-8** 일본어가 깨지는 자리가 없다 (화면·트레이 메뉴·안내문 txt 전부)

## G. 안내문

- [ ] **G-1** zip 안에 `はじめにお読みください.txt` 가 있고 파일 이름이 깨지지 않았다 — *미검증*
- [ ] **G-2** **메모장으로 더블클릭해서 열었을 때 글자가 깨지지 않는다**(UTF-8 BOM) — *미검증*
- [ ] **G-3** 줄이 한 줄로 뭉치지 않는다(CRLF) — *미검증*
- [ ] **G-4** 안내문에 적은 화면 문구·경로가 실제와 일치한다
      (특히 SmartScreen 문구, 「終了 (Orbit を閉じる)」, `%LOCALAPPDATA%\Orbit`)

## H. MSI (만들어졌을 때만)

- [ ] **H-1** `Orbit-<버전>.msi` 가 아티팩트에 있다 — *미검증(WiX 유무에 달림)*
- [ ] **H-2** 설치할 때 관리자 권한을 묻지 않는다(`--win-per-user-install`) — *미검증*
- [ ] **H-3** 시작 메뉴·바탕화면에 바로가기가 생긴다 — *미검증*
- [ ] **H-4** 제어판에서 제거하면 앱은 지워지고 `%LOCALAPPDATA%\Orbit\` 의
      데이터는 **남는다** — *미검증*

> 포터블 zip 이 주 배포 형태다. MSI 는 있으면 좋은 것이고, 여기서 문제가 나면
> 그냥 빼고 zip 만 넘겨도 된다.

## 문제가 생겼을 때 볼 것

| 무엇 | 어디 |
|---|---|
| 앱 로그 | `%LOCALAPPDATA%\Orbit\logs\orbit.log` |
| 지금 쓰는 포트 | `%LOCALAPPDATA%\Orbit\orbit.port` |
| 중복 실행 잠금 | `%LOCALAPPDATA%\Orbit\orbit.lock` |
| DB 파일 | `%LOCALAPPDATA%\Orbit\db\orbit.mv.db` |
| 사진 | `%LOCALAPPDATA%\Orbit\media\` |

콘솔 창이 없으므로 **화면에는 아무 오류도 보이지 않는다.** 뭔가 이상하면
`orbit.log` 가 유일한 단서다. 기동조차 못 해서 로그 파일이 아예 없다면, 그건
JVM 이 뜨기 전에 죽은 것이므로 런타임 이미지 문제(모듈 누락)를 의심할 것.

### 임시로 동작을 바꾸고 싶을 때

명령 프롬프트에서 환경변수를 주고 실행하면 된다. 확인용이지 사용자에게 안내할
내용은 아니다.

```
set ORBIT_PORT=18080
set ORBIT_OPEN_BROWSER=false
set ORBIT_HOME=C:\Users\%USERNAME%\Desktop\orbit-test
Orbit.exe
```

- `ORBIT_PORT` — 먼저 시도할 포트. 막혀 있으면 여기서부터 옆으로 훑는다
- `ORBIT_OPEN_BROWSER=false` — 브라우저 자동 실행만 끈다
- `ORBIT_HOME` — 데이터 폴더를 옮긴다. **깨끗한 상태로 첫 실행을 재현할 때 쓴다**
  (`%LOCALAPPDATA%\Orbit\` 을 지우지 않고도 초기 상태를 볼 수 있다)
